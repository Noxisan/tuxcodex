# elasticsearch-reset-password

> Setzt ein neues Passwort für einen eingebauten Elasticsearch-Benutzer wie `elastic` oder `kibana_system`, zufällig oder selbst gewählt.

![elasticsearch-reset-password output](../assets/screenshots/35-search/elasticsearch-reset-password.png)

## Syntax

```bash
sudo /usr/share/elasticsearch/bin/elasticsearch-reset-password -u BENUTZER [-i] [-b] [--url URL]
```

## Optionen

| Option | Beschreibung |
|--------|--------------|
| `-u BENUTZER` | Der Benutzer, z. B. `elastic` oder `kibana_system` |
| `-i` | Das neue Passwort selbst eingeben statt eines zufälligen |
| `-a` | Ein zufälliges Passwort erzeugen (der Standard) |
| `-b` | Batch-Modus: nicht nach Bestätigung fragen |
| `--url URL` | Adresse des Knotens, falls nicht `https://localhost:9200` |

Das Werkzeug braucht einen laufenden Knoten und ändert das Passwort über die API. OpenSearch hat kein solches Werkzeug; dort änderst du Benutzer im Security-Plugin (`internal_users.yml` oder REST-API).

## Beispiele

**Ein neues zufälliges Passwort für `elastic`:**

```bash
sudo /usr/share/elasticsearch/bin/elasticsearch-reset-password -u elastic
```

```text

The password will be printed in the console.
Please confirm that you would like to continue [y/N]y

```

**Das Passwort selbst wählen:**

```bash
sudo /usr/share/elasticsearch/bin/elasticsearch-reset-password -u kibana_system -i
```


## Wann brauche ich das?

- Direkt nach der Installation, wenn das beim Setup angezeigte Passwort verloren ist
- Wenn ein Admin geht, der das Passwort von `elastic` kannte
- Um vor dem Anbinden von Kibana das Passwort für `kibana_system` zu setzen

!!! tip "Nicht täglich als `elastic` arbeiten"
    `elastic` ist ein Superuser. Leg in Kibana oder über die API persönliche Benutzer mit
    passenden Rollen an und heb `elastic` für Notfälle im Passwortmanager auf.

!!! warning "Anwendungen fallen aus"
    Nutzt eine Anwendung oder Logstash den zurückgesetzten Benutzer, kann sie sich nicht mehr
    verbinden, bis ihre Konfiguration das neue Passwort hat. Prüf vorher, welche Dienste den
    Benutzer verwenden.

## Unterschiede zwischen Distributionen

| | Debian | Ubuntu | RHEL | Arch |
|---|--------|--------|------|------|
| Installation | APT-Paketquelle von Elastic | APT-Paketquelle von Elastic | YUM-Paketquelle von Elastic | AUR oder Container |
| Pfad | `/usr/share/elasticsearch/bin/` | `/usr/share/elasticsearch/bin/` | `/usr/share/elasticsearch/bin/` | je nach Paket |
